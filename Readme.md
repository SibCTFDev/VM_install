# Краткая инструкция по установке виртуальной машины

| Ваша система | Файл | Программа |
|--------------|------|-----------|
| Windows, Linux, macOS (Intel) | `.ova` | [VirtualBox](https://www.virtualbox.org/) |
| macOS (Apple Silicon M1/M2/M3) | `.utm` | [UTM](https://mac.getutm.app/) |

---

## Шаги для всех
0. **Создайте заявку в service desk на установку гипервизора(UTM или VirtualBox)** и подождите, пока она не будет согласована. Инструкция по созданию заявки находится ниже.
1. **Скачайте** нужный файл образа
   - [.ova](https://drive.google.com/file/d/1btag8nEhOrne-w02yGiKuNI57Uvi0a9R/view?usp=sharing) для Windows, Linux, macOS Intel
   - [.utm](https://drive.google.com/file/d/1bEoiuGXYXnuWYOVLTFIJ60911NqDvEA6/view?usp=sharing) для macOS на Apple Silicon
2. **Установите** гипервизор:
   - **VirtualBox** – с официального сайта (для Windows, Linux, macOS Intel).
   - **UTM** – с сайта или через `brew install --cask utm` (для macOS на Apple Silicon).
3. **Импортируйте** образ:
   - **VirtualBox**: *Файл → Импорт конфигурации* → выберите [.ova](https://drive.google.com/file/d/1jl-Fa1bBpFanj8PXTlqYP9H6HE-iINkn/view?usp=sharing) → настройте ОЗУ (минимум 4 ГБ, лучше 8) и число ядер CPU (2 и более) → *Импорт*.
   - **UTM**: нажмите `+` → *Импорт* → выберите [.utm](https://drive.google.com/file/d/1bEoiuGXYXnuWYOVLTFIJ60911NqDvEA6/view?usp=sharing) → *Сохранить*.
4. **Запустите** виртуальную машину кнопкой «Запустить» / «Play».

1. Войдите в NSD, нажмите кнопку добавления заявки
2. **Услуга:** Обслуживание рабочего места пользователя (IT) -> Программное обеспечение
3. **Тип заявки:** запрос на обслуживание
4. **Категория работ:** Обслуживание ПО

6. **Источник дистрибутива ПО:** возьмите информацию из пунктов 1 и 2 раздела "Шаги для всех" в зависимости от вашей ОС
7. **Обоснование:** для выполнения практических заданий в рамках обучения на курсе Ninja Dojo


## ⚠️ Частая ошибка VirtualBox: «Сетевые интерфейсы не найдены (wlo1)»

**Что происходит:**  
При запуске ВМ появляется окно с текстом:  
> *Не удаётся запустить виртуальную машину, поскольку следующие сетевые интерфейсы не были найдены: wlo1 (adapter 1).*

**Причина:**  
В образе прописано имя конкретного сетевого адаптера (например, `wlo1`) с компьютера, где создавался образ. На вашем устройстве этот интерфейс называется иначе (или отсутствует).

**Как исправить (два способа):**

### Способ 1 – прямо в окне ошибки
- Нажмите кнопку **«Изменить настройки сети»**.
- В открывшемся окне для **Адаптера 1** в поле **«Имя»** выберите существующий интерфейс (например, `en0`, `eth0`, `Wi-Fi` или `enp...`).
- Нажмите **ОК** и запустите ВМ снова.

### Способ 2 – через настройки ВМ
- Если окно ошибки закрыли, откройте VirtualBox, выберите нужную ВМ (не запуская).
- Нажмите **Настроить** → раздел **Сеть**.
- В открывшемся окне для **Адаптера 1** в поле **«Имя»** выберите существующий интерфейс (например, `en0`, `eth0`, `Wi-Fi` или `enp...`).
- Нажмите **ОК** и запускайте.

## Дополнительные советы

#### 0. **Гостевые дополнения VirtualBox** уже установлены.
#### 1. **UTM** на Apple Silicon работает «из коробки», дополнительные драйверы не требуются.
#### 2. **Если ВМ тормозит** – увеличьте выделенную оперативную память и количество ядер CPU (но не более 75% от физических ресурсов хоста).
#### 3. **При ошибке VT-x/AMD-V** – зайдите в BIOS/UEFI и включите аппаратную виртуализацию (**Обратитесь к сервис инженеру!**).
#### 4. Не работает интернет внутри Debian x64
##### Шаг 1. Проверьте подключение без корпоративной сети
1. Отключитесь от корпоративной сети/VPN.
2. Полностью выключите виртуальную машину.
3. Закройте и заново запустите VirtualBox.
4. Запустите виртуальную машину повторно.
Часто этого достаточно для восстановления подключения. Если интернет по-прежнему не работает, переходите к следующему шагу.
##### Шаг 2. Проверьте настройки сетевого адаптера VirtualBox
1. **Полностью выключите** виртуальную машину (не используйте сохранение состояния).
2. В VirtualBox выберите нужную виртуальную машину.
3. Нажмите **Настроить** (область **1** на скриншоте).
4. Перейдите в раздел **Сеть** (область **2**).
5. Откройте вкладку **Адаптер 1** и проверьте настройки (область **3**):
   - **Включить сетевой адаптер** – включено.
   - **Тип подключения** – `NAT`.
   - **Подключить виртуальный кабель** – включено.
6. Если настройки верные, но интернет не работает, попробуйте сгенерировать новый MAC-адрес с помощью кнопки, отмеченной цифрой **4**.
7. Нажмите **ОК**, запустите виртуальную машину и проверьте доступ в интернет.

#### 5. Firefox показывает ошибку "The proxy server is refusing connections"
**Причина:** Firefox пытается подключиться через прокси-сервер, который недоступен или не запущен. Это может быть связано с настройками Firefox или расширения FoxyProxy.
##### Шаг 1. Отключите прокси в Firefox
1. Откройте Firefox внутри виртуальной машины и введите в адресную строку `about:preferences#connectionSecurity`.
2. Найдите `Proxy settings` и перейдите в `Configure proxy`
3. Выберите **No proxy / Без прокси**.
4. Попробуйте зайти на https://ninja.yc.ftc.ru/ или https://sectasks.yc.ftc.ru.
Если проблема сохранилась, переходите к следующему шагу.
##### Шаг 2. Отключите FoxyProxy
1. Откройте список расширений Firefox.
2. Найдите расширение **FoxyProxy**.
3. Откройте его настройки и выберите **Disable**.
4. Подождите 2–3 минуты и попробуйте открыть сайты снова.
> **Важно для работы с Burp Suite:** после отключения FoxyProxy запросы обычного Firefox перестанут автоматически проходить через прокси Burp Suite.
>
> Для перехвата HTTP-запросов используйте **встроенный браузер Burp Suite** (*Proxy → Intercept → Open Browser*). Если впоследствии потребуется использовать Firefox для перехвата, настройки прокси нужно будет восстановить.
#### 6. В VS Code не отображается расширение Gaechka или не загружаются задания
**Важно:** сначала убедитесь, что интернет внутри виртуальной машины работает + **Gaechka требует подключения к корпоративной сети**.
##### Шаг 1. Подключитесь к корпоративной сети
Подключитесь к корпоративной сети через **MA**. Без корпоративного подключения расширение не загрузит задания.
##### Шаг 2. Переподключите сеть виртуальной машин
После подключения к корпоративной сети через MA обновите сетевое соединение внутри Debian.
1. Откройте меню сети в верхней части рабочего стола Debian.
2. Найдите подключение **Wired connection 1**.
3. Отключите его через **Disconnect**, затем подключите снова.
4. Дождитесь восстановления соединения.
5. Если подключение не восстановилось, попробуйте перезапустить VM.
<img src="https://github.com/crono533/VM_install/blob/fix/new_additional_advices/Pasted%20image%2020261007163204.png" width="500">

##### Шаг 3. Перезапустите VS Code
1. Полностью закройте VS Code.
2. Откройте терминал в папке с заданиями.
3. Запустите VS Code повторно (code .)
##### Шаг 4. Проверьте Workspace Trust
Расширение может работать некорректно, если папка с заданиями открыта в недоверенном рабочем пространстве.
1. В VS Code нажмите **Ctrl + Shift + P**.
2. Введите `Workspaces: Manage Workspace Trust`.
3. Откройте найденный пункт.
4. Установите доверие к папке с заданиями, выбрав **In a Trusted Folder**.
##### Шаг 5. Проверьте работу расширения
1. Подождите, пока VS Code инициализирует расширения.
2. Проверьте, появилось ли расширение **Gaechka**.
3. Убедитесь, что задания курса загрузились.
